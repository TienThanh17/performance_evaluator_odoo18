# Role
Bạn là một Senior Odoo 18 Developer và chuyên gia về Business Intelligence (BI) Dashboard. 

# Context & Objective
Tôi đang xây dựng module KPI Dashboard. Hiện tại, model `hr.kpi.dashboard.widget` đang quản lý cấu hình các biểu đồ Macro (Tổng hợp) như Trend Line, Distribution. 
Tuy nhiên, các cấu hình trục X (Group By) và trục Y (Measure) đang dùng field dạng `Char` (hardcode text), và có một field `scope` bị dư thừa.
Mục tiêu của bạn là:
1. Xóa bỏ field `scope`.
2. Chuyển đổi `measure_field` và `group_by` thành field `Many2one` trỏ tới `ir.model.fields` (Dynamic Query Builder).
3. Triển khai logic tính toán bằng `read_group` cho 2 hàm `_build_macro_trend` và `_build_macro_distribution` trong service vẽ biểu đồ.

# Yêu cầu thực thi chi tiết (Vui lòng làm theo 3 bước sau)

## Bước 1: Cập nhật Model `hr.kpi.dashboard.widget`
- XÓA CÁC TRƯỜNG CŨ: `scope`, `measure_field` (Char), `group_by` (Char).
- THÊM CÁC TRƯỜNG MỚI SAU:
  1. `measure_field_id`: Many2one trỏ đến `ir.model.fields`. Domain bắt buộc model là 'hr.kpi.evaluation' và `ttype` thuộc ['float', 'integer', 'monetary'].
  2. `group_by_field_id`: Many2one trỏ đến `ir.model.fields`. Domain bắt buộc model là 'hr.kpi.evaluation' và `store` = True.
  3. `group_by_ttype`: Char, related tới `group_by_field_id.ttype` (để dùng ẩn hiện UI).
  4. `date_granularity`: Selection (day, week, month, quarter, year), mặc định là 'month'.
  5. `filter_domain`: Đổi từ Char sang Text.

## Bước 2: Cập nhật XML Form View của Widget
Cập nhật vùng cấu hình biểu đồ Macro:
- Xóa các field cũ (`scope`, `measure_field`, `group_by`).
- Hiện `measure_field_id` và `group_by_field_id` (với `options="{'no_create': True}"`). Các field này ẩn (`invisible`) nếu `macro_widget_type == 'radar_chart'`.
- Thêm field `group_by_ttype` (invisible="1").
- Thêm field `date_granularity` (chỉ hiện và bắt buộc nhập khi `group_by_ttype` in ['date', 'datetime']).
- Hiện field `filter_domain`.

## Bước 3: Triển khai Logic ở Chart Service (`hr_kpi_dashboard_chart_service.py`)
Viết 2 hàm `_build_macro_trend` và `_build_macro_distribution` nhận tham số `(self, evaluation, widget)`. 
Bắt buộc import `safe_eval` từ `odoo.tools.safe_eval`.

**Logic bắt buộc cho cả 2 hàm:**
1. **Xác định Measure (Trục Y) và Group By (Trục X):**
   ```python
   measure = widget.measure_field_id.name or 'final_score'
   groupby_name = widget.group_by_field_id.name or 'employee_id'
   
   if widget.group_by_ttype in ['date', 'datetime'] and widget.date_granularity:
       groupby = f"{groupby_name}:{widget.date_granularity}"
   else:
       groupby = groupby_name
       ```
2. **Hàm _build_macro_trend:**

Base Domain: [('state', '=', 'done')].

Phân loại theo dashboard_kind: + Nếu widget.dashboard_kind == 'individual': Nối thêm domain ('employee_id', '=', evaluation.employee_id.id). Màu chart: #3b82f6.

Nếu widget.dashboard_kind == 'department': Nối thêm domain ('department_id', '=', evaluation.department_id.id). Màu chart: #10b981.

Áp dụng safe_eval(widget.filter_domain) nếu có.

Dùng read_group với fields=[f"{measure}:avg"], groupby=[groupby], limit=6, orderby=f"{groupby} desc". Đảo ngược list kết quả và trả về mảng cho Line Chart.

3. **Hàm _build_macro_distribution:**

Base Domain: [('department_id', '=', evaluation.department_id.id), ('period_id', '=', evaluation.period_id.id), ('state', 'not in', ['draft', 'cancel'])].

Áp dụng safe_eval(widget.filter_domain) nếu có.

Dùng read_group tính avg. Sắp xếp giảm dần theo điểm số.

Trả về Bar Chart.

Logic tô màu: Lặp qua kết quả, nếu widget.dashboard_kind == 'individual' và record đó thuộc về evaluation.employee_id.id thì tô màu #f59e0b (Vàng nổi bật), các cột khác màu #e5e7eb. Nếu widget.dashboard_kind == 'department' thì tô toàn bộ #3b82f6 (Xanh đồng đều). Chú ý parse tuple của Many2one field khi lấy giá trị groupby.
